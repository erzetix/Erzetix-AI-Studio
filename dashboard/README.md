# Дашборд клиента

## Роль в системе

Единственная подсистема, с которой клиент взаимодействует напрямую. Обеспечивает постановку задач, просмотр материалов, утверждение контента и доступ к показателям эффективности кампаний.

Контур Human-in-the-Loop реализован средствами дашборда: утверждение и отклонение материалов выполняется в интерфейсе дашборда.

## Зона ответственности

- Формирование брифа кампании и передача его оркестратору
- Участие клиента в разработке профиля персонажа
- Отображение статуса кампаний в производственном конвейере
- Отображение сформированных материалов
- Утверждение и отклонение материалов в контуре Human-in-the-Loop
- Отображение показателей эффективности публикаций
- Формирование отчётов об эффективности кампаний
- Предоставление режима гостевого входа для демонстрационных целей

## Режимы утверждения

| Код | Порядок утверждения |
|---|---|
| `manual` | Каждый материал утверждается человеком |
| `hybrid` | Утверждение человеком требуется для материалов, получивших заключение `escalated` либо не прошедших отдельные категории проверок |
| `autonomous` | Утверждение человеком не требуется, материалы с заключением `approved` передаются в модуль публикации |

Режим устанавливается отдельно для каждого клиента или персонажа.

## Режим гостевого входа

Предусмотрен для демонстрации возможностей комплекса. В режиме гостевого входа доступен просмотр демонстрационных кампаний и материалов. Операции утверждения материалов, изменения профиля персонажа и формирования брифов недоступны. Данные действующих клиентов в режиме гостевого входа не отображаются.

## Роли пользователей

| Роль | Доступные операции |
|---|---|
| `client` | Формирование брифов, просмотр материалов и метрик, утверждение материалов |
| `content_specialist` | Утверждение материалов, ввод показателей эффективности публикаций |
| `guest` | Просмотр демонстрационных материалов |

## Точки входа

Перечень точек входа приведён в [`api.py`](api.py).

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/campaigns` | Создание кампании на основании брифа |
| `GET` | `/campaigns` | Получение списка кампаний |
| `GET` | `/campaigns/{campaign_id}` | Получение состояния кампании |
| `GET` | `/campaigns/{campaign_id}/materials` | Получение материалов кампании |
| `POST` | `/materials/{material_id}/approve` | Утверждение материала |
| `POST` | `/materials/{material_id}/reject` | Отклонение материала с указанием причины |
| `GET` | `/campaigns/{campaign_id}/metrics` | Получение показателей эффективности |
| `POST` | `/campaigns/{campaign_id}/metrics` | Ввод показателей эффективности публикаций |
| `GET` | `/campaigns/{campaign_id}/report` | Формирование отчёта об эффективности |
| `GET` | `/characters/{character_id}` | Получение профиля персонажа |

## Выходной контракт

Представление материала, передаваемое интерфейсу:

```json
{
  "material_id": "mat_001",
  "campaign_id": "camp_2026_demo",
  "draft_id": "drf_001",
  "format": "short_video",
  "state": "awaiting_approval",
  "preview_ref": "storage://media/camp_2026_demo/ast_001.mp4",
  "caption": "Сопроводительная подпись к публикации",
  "guardian_verdict": "approved",
  "failed_checks": [],
  "created_at": "2026-09-01T19:30:00Z"
}
```

Поле `preview_ref` содержит ссылку на материал в хранилище. Выдача содержимого выполняется с проверкой прав доступа пользователя.

## Модель данных и точки входа

- [`models.py`](models.py) — структуры данных: представление материала, представление кампании, решение об утверждении, показатели эффективности
- [`api.py`](api.py) — перечень точек входа и контракт операций (без реализации логики)

## Взаимодействие с подсистемами

1. Дашборд передаёт бриф оркестратору и получает идентификатор кампании
2. Состояние кампании запрашивается у оркестратора
3. Материалы с заключением агента-хранителя бренда отображаются в контуре утверждения
4. Решение об утверждении передаётся оркестратору и определяет дальнейший переход состояния кампании
5. Показатели эффективности, введённые специалистами по производству контента, передаются агенту-аналитику метрик

## Обработка ошибок

- При недоступности оркестратора отображается последнее известное состояние кампании с указанием времени получения данных; операции утверждения в этом случае недоступны
- Утверждение материала, не находящегося в состоянии `awaiting_approval`, отклоняется с кодом `INVALID_MATERIAL_STATE`
- Операции, недоступные роли пользователя, отклоняются с кодом `FORBIDDEN` без раскрытия сведений о существовании запрошенного объекта
- Запрос материалов действующих клиентов в режиме гостевого входа отклоняется с кодом `FORBIDDEN`
